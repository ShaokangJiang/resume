# Shaokang Jiang's academic website and résumé

Three site versions share the existing content engine:

- `index.html`: modern homepage with the introduction, published first-author papers (including arXiv preprints unless under review), compact education, and awards and activities. Generated by the actual [al-folio](https://github.com/alshedivat/al-folio) theme (`al_folio_core` 1.0.15), Jekyll, and Jekyll Scholar. The theme supplies the layouts, typography, styles, publication cards, and fonts.
- `publications/index.html`: modern complete publication list, including coauthored papers and manuscripts under review.
- `experience/index.html`: modern research, teaching, and industry experience, with Research selected by default.
- `projects/index.html`: modern detailed projects and technical skills.
- `pure.html`: plain HTML using browser defaults and no custom CSS, with the complete paper list and résumé sections.
- `rabbit.html`: original illustrated résumé design, based on [Simple-CV](https://github.com/dcetin/Simple-CV), with the current introduction and shared publication renderer.
- `pdf.html`: existing PDF viewer; direct downloads use `final/research/Shaokang_Jiang_Resume.pdf`.

Edit `js/site-data.js` for the introduction, contact links, and modern/pure education entries. The research focus is end-user programming and personal software, connected with developer tools and programming assistants.

All versions use the original shared publication database, `pub.bib`. The modern Publications page, pure page, and rabbit page show the complete list, including manuscripts marked under review. The modern homepage shows first-author papers with a public record, including arXiv preprints, and excludes entries marked under review, submitted, unpublished, or in preparation. `js/publication-policy.js` applies the same rule during compilation and live rendering; use the BibTeX `status` or `note` field to record review status. Experience and projects use `experience-source.js` and `project-source.js`; the modern Projects page and pure page also read `Skills.tex`. No publication thumbnails are required. The rabbit page retains its education, skills, project gallery, experience timeline, and original navigation header.

Access the three versions directly at `https://resume.shaokang.me/`, `/pure.html`, or `/rabbit.html`. The custom domain is set in `CNAME`; the old `https://shaokangjiang.github.io/resume/` address redirects there through GitHub Pages. There are no page-switch links. The modern site uses al-folio's default header with only about, publications, experience, projects, and cv as page links, in that order, plus the search and light/dark theme controls. Publications, Experience, and Projects have separate pages, and CV opens the PDF viewer. The pure page has no navigation bar. The rabbit page keeps its original desktop section links, mobile side menu, blog button, and PDF button. The modern Experience page, pure page, and rabbit page filter experience through All, Research, and TA & Work buttons; project preview buttons on the rabbit page open dialogs within the current page.

The modern pages are static HTML so search crawlers can read them without running JavaScript. At build time, `scripts/prepare-modern.js` compiles the introduction, links, and education (`js/site-data.js`), every experience entry (`experience-source.js`), the projects (`project-source.js`), the technical skills (`Skills.tex`), and the homepage awards and activities (the "Awards and Activities" list in `Resume_research.tex`) into `modern/_data/academic.json`, which the templates in `modern/_pages/` render with the shared snippets in `modern/_includes/`. The Experience filter buttons only show or hide the compiled entries. The modern pages use al-folio's compiled bibliography when it matches `pub.bib`; if the bibliography changes before the next build, the browser refreshes the paper rows using the same theme markup. `pure.html` and `rabbit.html` still render these sections from the shared sources on page load.

To rebuild the modern page on Windows, run `./scripts/build-modern.ps1` from PowerShell. It uses native Ruby/Bundler when available, otherwise the installed Ubuntu WSL distribution. Node.js and Ruby 3.2 or later with Bundler are required. The configured Ubuntu build uses the official Ruby 3.3.12 binary in `/opt/hostedtoolcache/Ruby/3.3.12/x64`; it does not replace system Ruby. Dependencies are isolated in `modern/vendor/bundle` for native Ruby or `~/.cache/resume-al-folio/bundle` inside Ubuntu; the exact versions are recorded in `modern/Gemfile.lock`.

The build prepares the shared data, runs `bundle exec jekyll build`, audits local theme overrides, copies the four modern pages and theme assets to the repository root, and writes their Markdown copies (see below). The copy step converts local resource and navigation URLs to relative paths at each page's directory depth so the same output works at any path, both locally and at `https://resume.shaokang.me/`; canonical URLs use the custom domain. Shared scripts and styles receive content hashes to refresh browser caches after a rebuild. `modern/upstream-config.yml` retains the official starter defaults; `scripts/prepare-modern.js` writes the personal configuration and derived bibliography without changing the original sources. Edit templates in `modern/_pages/` rather than the generated HTML files.

The default navigation header, about layout, name treatment, bibliography layout, Sass, fonts, and runtime scripts come from the official theme packages, with no local theme overrides. `modern/_plugins/navigation.rb` supplies the site's navigation destinations to the default header without generating placeholder pages. `css/al-folio-content.css` arranges the existing résumé entries and offsets section anchors below the fixed header; it does not replace the theme typography or publication styling. Roboto font files are served locally with their upstream license.

The local BibTeX reader in `js/bibtex.js` supports braced and quoted fields, nested braces, escaped percent signs, line comments, and concatenated values. The source files remain compatible with the existing Node.js résumé generators.

Serve the repository over HTTP so the browser can load the bibliography and skills, for example `python -m http.server 8000`. Open `http://localhost:8000/`, `/publications/`, `/experience/`, `/projects/`, `/pure.html`, or `/rabbit.html`. The same files are served at `https://resume.shaokang.me/` on GitHub Pages. Opening files directly with `file://` prevents browsers from fetching the content sources.

Rebuild the modern pages with `./scripts/build-modern.ps1` after editing `js/site-data.js`, `experience-source.js`, `project-source.js`, `Skills.tex`, the awards in `Resume_research.tex`, a template, the theme configuration, or dependencies; until then, the modern pages show the previous build (publications excepted, as above). `pure.html` and `rabbit.html` update from the shared sources on page load. PDF files are separate generated artifacts; linking them does not regenerate them.

The research résumé reads the existing `experience-source.js` data without modifying it. The teaching section uses the compact TA entries, `filterAndCombine(source, ["TA-combined"], new Date("January 2020"))`, which read `source_combined.TA` (one entry per university) and render each detail as its own bullet. Run `node experience-research.js --research-only` to regenerate `Experience_Research.tex` and `Experience_Teaching_Short.tex` without changing the full teaching résumé sections, then run `latexmk -pdf Resume_research.tex` and copy the PDF to `final/research/Shaokang_Jiang_Resume.pdf` for the site's CV download. The research résumé adds a clickable paper link from each publication's BibTeX `url` field.

## Markdown for AI agents

The build also writes a Markdown copy beside each modern page (`index.html.md`, `publications/index.html.md`, `experience/index.html.md`, and `projects/index.html.md`) and an `llms.txt` index that links to them, following the [llms.txt](https://llmstxt.org/) convention. `scripts/markdown-modern.js` builds them from the same compiled data as the HTML pages, so they list the same content: the homepage shows the selected papers, the Publications copy lists every paper, and the Experience copy lists all entries under the Research and Teaching & work groups used by the filter buttons. Each HTML page links to its copy with `<link rel="alternate" type="text/markdown">`. GitHub Pages serves these files as they are, so agents can read them without any other setup.

To also answer requests that ask for Markdown (`Accept: text/markdown`), which is what Cloudflare's paid "Markdown for Agents" setting does, deploy the free Worker in `cloudflare/markdown-worker.js`. It returns the Markdown copy when a request asks for Markdown at least as strongly as HTML, and passes every other request through unchanged, so browsers and search crawlers still get the HTML pages.

1. In the Cloudflare dashboard, open Workers & Pages, create a Worker from the Hello World template, open the code editor, replace its code with `cloudflare/markdown-worker.js`, and deploy it.
2. In the Worker's settings, under Domains & Routes, add the route `resume.shaokang.me/*` for the `shaokang.me` zone, and set its failure mode to fail open so the normal site still loads if the free plan's daily request limit is ever reached.
3. Keep the `resume` DNS record proxied (orange cloud), since Workers only run on proxied traffic, and leave Cloudflare's paid "Markdown for Agents" setting off.
4. Check it with `curl -H "Accept: text/markdown" https://resume.shaokang.me/experience/`, which should return Markdown, while the same command without the header returns HTML.

The Worker only needs redeploying if `cloudflare/markdown-worker.js` changes; rebuilding and pushing the site updates the Markdown it serves.
